# 疲劳计算过程：明天汇报提纲与讲稿
本材料对应本次上传的fatigue_calculate.m。核心代码与当前版本一致。建议讲述时间约5—7分钟，取决于公式解释程度；PPT每页备注也已写入对应讲稿。

## 第1页：汇报主线：疲劳怎样进入这套模型

今天主要介绍疲劳计算过程。模型在固定幅值荷载下，采用循环块的准静态峰谷平衡计算。它用局部界面滑移判断疲劳是否激活，再通过节点黏结峰值退化，把循环历史传递到后续受力响应中。循环数增加并不意味着所有节点按同一程度退化。

核心句：局部滑移 → 活跃节点 → 局部龄期 → 黏结退化 → 响应重分配
代码定位：fatigue_calculate：主控制；active_nodes、bond_strength：局部疲劳规则

## 第2页：先区分三个循环量和一份历史

这里有三个容易混淆的量。N是整体计算已经接受的循环数，Ni是各节点的局部龄期，ΔN是本步打算推进多少次。一个节点只有处于活跃状态时才增加Ni。memory保存不可逆历史，也是计算重试时回到的基准。虽然候选数据可能反复计算，已接受的历史不会随意被覆盖。

核心句：整体循环数 N ≠ 所有节点共享的局部循环数 Ni
代码定位：fatigue_calculate：create_memory；update_memory

## 第3页：第1步：建立初始峰谷响应

疲劳更新之前，必须先知道这个荷载范围下的初始峰谷响应。程序先求峰值平衡，再用峰值的最大滑移历史求谷值。两次计算的目的，是取得每个节点的峰谷滑移差，而不是只看峰值滑移。N等于零表示尚未提交疲劳循环更新，不表示没有外荷载。

核心句：Vc + Vs + Vf = Qmax/2；   Vc + Vs + Vf = Qmin/2
代码定位：fatigue_calculate第18–54行；state → trial

## 第4页：第2步：判断活跃节点并提出局部龄期更新

当前程序的活跃判断有两道门槛。节点需要达到滑移阈值或已经激活，同时本步仍然有足够的峰谷滑移差。因此，以前激活过的节点在没有循环滑移时，也不会继续计数。确定活跃节点后，update_memory只在这些节点增加局部龄期。0.75阈值有参考论文依据，历史保持与滑移差容差是代码实现规则。

核心句：Ni,proposed = Ni,accepted + ΔN（仅活跃节点）
代码定位：active_nodes；fatigue_calculate第58行及第232–246行

## 第5页：第3步：把局部龄期转成黏结退化

接下来，程序把局部龄期转换成节点的峰值黏结应力。这一步的公式在bond_strength中，实际通过state、trial被调用，不是在update_memory里直接完成。以当前条材初始峰值15.72MPa为例，同一活跃节点由100次推进到120次后，峰值从约9.479MPa降到9.232MPa。这只是公式代入示例，不是一组新增的试验结果或整梁模拟结果。

核心句：τm,i = max{0, τm,0[1 − kf log₁₀max(Ni,1)]}
代码定位：bond_strength；Chen, Wang & Cheng (2019), IJ Fatigue, Eq. (2), DOI:10.1016/j.ijfatigue.2019.04.039

## 第6页：第4步：退化后重新平衡，决定接受还是重试

疲劳更新之后，不能直接假定结构仍然平衡。程序需要用退化后的黏结关系重算峰值响应。如果失败或位移跳得过大，就在循环块大于一次的前提下减半。每次重试都从同一份已接受历史出发，不把错误候选累积进去。峰值通过后，还要检查谷值。当前代码只对上述峰值情况减半，谷值失败则返回诊断。两状态都成功，才真正提交这一步。

核心句：proposed = update_memory(...) → state(...proposed...) → accept / retry
代码定位：fatigue_calculate第106–155行；state → trial → bond_strength / anchorage

## 第7页：第5步：循环块控制与停止条件

循环块是数值近似，作用是提高效率。程序不逐周期连续解析完整波形，也不是完整滞回时程积分。在一个块内，活跃节点按块起点的峰谷响应确定，因此需要检查循环步长敏感性。达到Nmax只说明算到了设定上限。如果最小块仍找不到指定域内的平衡，或局部求解不收敛，应报告相应原因，不能全部叫物理脱黏破坏。

核心句：达到 Nmax 是 runout；单根筋失效后仍需检查整体平衡
代码定位：fatigue_calculate第72–100行、第117–145行及最终状态整理

## 第8页：明天汇报的结论与当前范围

本次汇报着重说明计算框架已经怎样运行，而不是宣称所有破坏机制已经完整建立。当前默认主要研究局部界面疲劳退化引起的响应变化。混凝土提供经验抗剪贡献，FRP有固定抗拉上限，但它们不等于完整的混凝土和FRP本体疲劳模型。此外，前面的审查提示疲劳增量对网格较敏感，因此下一阶段需要继续收敛研究和试验验证。

核心句：建议表述：基于局部界面疲劳退化的抗剪平衡迭代计算框架
代码定位：当前上传fatigue_calculate与仓库计算实现一致；本次仅制作汇报材料，未修改源码

## 一分钟总结

本程序先求当前荷载范围下的峰值和谷值响应，再通过滑移阈值与峰谷滑移差识别疲劳活跃节点。只给这些节点累计局部循环数，并使用局部疲劳退化律降低峰值黏结应力。随后重新求峰谷平衡；必要时减小循环块重试。两状态都成功才更新整体循环数与已接受历史。这是一套基于局部界面退化的准静态抗剪疲劳迭代框架，后续仍需网格收敛与试验验证。
